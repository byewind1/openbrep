# OpenBrep v0.10.10 发布说明

**发布日期**：2026-09-21

## 更新要点

- feat: 预览材质落地 —— 语义材质预设、命名 GDL 材质真实渲染、材质变化写入验收报告
- feat: Codex 新增「本机配置」入口，可跟随你已有的 `~/.codex`，与托管登录并存
- feat: 支持 cc-switch 多供应商 Codex 路由，模型按供应商分组并自动刷新目录
- feat: 交付可信度 —— 成功修改绑定真实 after-revision，部分交付 / 快照失败如实展示
- feat: 结构化参数编辑与生效参数观测（原子参数修改 + 参数角色推断）
- feat: 技能提案可审阅、可恢复审批，未审批候选绝不进入技能检索
- feat: 创建会话隔离与批量删除历史
- fix: 预览棚光与色调映射调整，材质 ID 大小写匹配，材质变化不再静默

## 一句话总结

本版本把「预览可信」和「交付可信」两条线补齐：预览终于能真的显示材质，
交付结果一律绑定真实源指纹与 after-revision —— 改没改、改到哪一步必须拿证据说话；
Codex 接入同时拆出「跟随本机配置」入口，并支持 cc-switch 多供应商路由。

## 变更明细

### 预览材质（本次最直观的变化）

- 新增 `openbrep/materials.py`：离线材质文档（项目内 `.openbrep/materials.json`）
  与四套预设 —— 木材 / 金属 / 玻璃 / 塑料，各自带颜色、粗糙度、金属度、
  透明度与 IOR。
- **语义材质预设**：按参数名、参数描述与用户指令推断材质家族。
  「浅色橡木桌面，黑色金属桌腿」会推出 `mat_top`=wood、`mat_leg`=metal，
  而不是所有构件共用一个灰模。
- **命名 GDL 材质真实生效**：脚本里的 `DEFINE MATERIAL "name"` 与
  `MATERIAL "name"` 现在会真正作用到预览网格；材质 ID 大小写不敏感匹配，
  `mat_top` 与 `MAT_TOP` 不再被当成两个材质。
- **没有材质文件时按参数推断兜底**：不再退回灰色占位。以 `chair_ok` 为例，
  8 个网格全部解析为木材，未解析网格数为 0。
- **材质变化进入验收报告**：MODIFY 前后材质对比会写进验收摘要；
  材质解析不出来的网格明确报 warn，不会伪装成通过。
- **预览棚光与色调映射**：改用 AgX 色调映射 + RoomEnvironment 环境光，
  弱光下不再一片死黑。
- 新增 `openbrep/runtime/visual_self_check.py`：用真实 Three.js 渲染截图做
  视觉自检（与前端同一套光照参数），Playwright 缺失或环境受限时返回
  `unverified` 并说明原因 —— 状态是「没验成」，不是「验过了」。
- 受影响模块：`openbrep/workbench/preview_service.py`、
  `openbrep/runtime/modify_acceptance.py`、
  `frontend/src/components/PreviewViewport.tsx`（有材质时默认进入材质模式）。
- 已知边界：兜底材质是离线近似，**不会**写回 `paramlist.xml` 的 Archicad
  材质索引；真实 Archicad 索引始终原样保留。

### Codex 接入

**双入口（本机配置 / 托管登录）**

- 由于此前 `CODEX_HOME` 被隔离到 OpenBrep 私有目录，打包版读不到用户终端里
  已经配好的 Codex，表现为「连不上 / 没有模型」。本版本新增 `local` 入口：
  跟随 `CODEX_HOME`（未设置时用标准 `~/.codex`），只读解析其中的模型与
  provider 配置，**不管理认证** —— `codex login`、provider 切换、key 管理
  全部留在 Codex CLI 那一侧。
- 默认行为不变：仍是 OpenBrep 托管登录，既有配置与连接向导不受影响；设置页
  可一键切换，本机配置入口在 UI 上标为推荐。
- 互斥锁迁到 `~/.openbrep/run/`（可用 `OPENBREP_CODEX_LOCK_DIR` 覆盖），
  `local` 入口不再向 Codex home 写任何文件。
- 状态区分 `no_cli` / `unconfigured` / `signed_out` / `ready`，并回传入口与
  home 来源；登录 / 登出 / 取消 / 限流只对托管入口开放。
- `codex` 可执行文件改为回退到用户登录 shell 的 PATH（带缓存），打包应用
  能找到只在 shell 里存在的 codex。

**cc-switch 多供应商路由**

- 新增 `openbrep/codex/cc_switch.py`：只读读取 cc-switch 的供应商注册表
  （含 SQLite），对外只暴露展示元数据，密钥字段不进 repr、不进错误信息。
- 模型列表按 cc-switch 供应商分组，支持目录开关控制与自动刷新；新增结构化
  模型引用（`provider/model`），未列出的模型 ID 也允许显式指定。
- Codex 运行时按供应商隔离，冲突错误原样保留，不再静默降级。

### 交付可信度（旋转楼梯工程契约 ST02 / ST03 / ST07 / ST08）

- 新增 `openbrep/source_fingerprint.py`：对受管源文件集合（顶层 `*.xml` +
  `scripts/**`）计算确定性 SHA256 指纹，保留 BOM，不纳入 `.openbrep` / 文章 /
  GSM，形如 `sha256:<hex>`。
- 新增 `openbrep/runtime/delivery_finalizer.py`：任何成功的源码修改都能从质量
  记录定位到准确的 after-revision；失败不允许伪造 after。
- 新增 `openbrep/workbench/delivery_presentation.py` + 前端 `DeliveryCard`：
  区分「已验证修改 / 部分修改 / 快照失败 / 旧记录未关联 / 声称修改但没有 diff」
  五种展示，部分交付不再显示成功总绿勾，失败给可恢复的下一步。
- 新增 `openbrep/workbench/host_verification_service.py`：宿主验证绑定到精确
  产物（源指纹 + 产物指纹），不再按「最近一次」模糊匹配。
- 修订记录补齐真实工作树 diff 与交付历史持久化，续接链接只消费一次。

### 参数编辑与观测（ST06）

- 新增 `openbrep/parameter_mutations.py`：`paramlist.xml` 的无损原子结构化
  修改，UI 与两条 MODIFY 链路共用同一份域实现。
- 新增 `openbrep/parameter_observation.py`：只读推断参数角色与生效值，
  只证明顶层、无条件、标量且依赖图无环的赋值，其余一律保持 unknown，
  交给调用方显式处理。
- 参数面板与语义验证接入上述观测，参数冲突 / 驱动参数错误可被指出。

### 技能沉淀（ST04）

- 新增 `openbrep/skill_proposals.py` + `openbrep/workbench/skill_proposal_service.py`：
  「把这轮修改沉淀成技能」走显式提案路径，候选先原子落盘到项目
  `.openbrep/memory/skill-proposals/`，用户审批（draft → approved / rejected）
  后才进入既有 propose + verify 双闸。
- 未审批候选**不进入** SkillsLoader 检索路径，审批流程可恢复、结论必须绑定证据。

### 其他

- 创建（CREATE）会话相互隔离，历史支持批量删除。
- 新增 `openbrep/contracts/stair.py`：显式绑定的螺旋楼梯工程合同求值，
  只消费既有 Master 解释器与 3D 预览产出的证据，不按项目名猜适用范围、
  不解析 GDL 表达式、不修改项目源。
- 新增 `openbrep/file_blocks.py`，交付文件块解析收敛到单一实现。
- 质量台账与跨脚本检查补齐真值判定。

## 已知边界

- 视觉截图自检依赖 Playwright + Chromium；未安装或系统权限受限时状态为
  `unverified`（明确未验证，不冒充通过）。可用 `OPENBREP_VISUAL_CHECK=1/0`
  强制开关。
- 材质兜底预设是离线近似值，用于预览观感；真实 Archicad 材质仍以
  `paramlist.xml` 中的索引为准。
- macOS 安装包仍未签名，首次打开可能需要在「右键 → 打开」中确认。

- 安装包用户：应用内一键更新（v0.9.2 及之后版本均支持），或从 Release 页

- 源码用户：`git pull && pip install -e "."`；`OPENBREP_VISUAL_CHECK` 与
