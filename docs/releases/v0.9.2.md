# OpenBrep v0.9.2 发布说明

**发布日期**：2026-09-14

## 一句话总结

桌面版自动更新上线：安装一次后，新版本出现时顶栏版本入口会有「有更新」徽标，点开即可看到更新要点（新增/修复分类），一键下载、验签、安装并自动重启；同时安装包换上了 OpenBrep 品牌图标（之前是 Tauri 脚手架的占位蓝块）。

---

## 变更明细

### 桌面端自动更新（tauri-plugin-updater + GitHub Releases）

- `src-tauri/`：注册 updater / process / opener 插件；新增 `updater_check`、`updater_download_and_install`、`app_version`、`open_releases_page` 自定义命令。走 Rust 自定义命令而非 JS 插件 API——工作台窗口加载的是后端 sidecar 的 localhost 外部 URL，自定义命令不受 capability ACL 限制；capabilities 仅需补 `remote.urls`（localhost 任意端口）让下载进度事件可达
- `tauri.conf.json`：`bundle.createUpdaterArtifacts` + `plugins.updater`（minisign 公钥 + `releases/latest/download/latest.json` 端点）；更新包经私钥签名，客户端验签后才安装，私钥只存在维护者本机与 GitHub secrets
- 前端（Hermes 式交互）：
  - 顶栏状态区版本 pill：显示当前版本，检测到新版本时出现「有更新」徽标，点击弹出更新对话框
  - `UpdateDialog`：版本对比、**更新要点列表**（从 Release notes 解析 bullet，按 feat/fix 前缀分为 新增/修复/其他 徽标，剥离 `by @user in .../pull/N` 尾缀，去重封顶 8 条）、下载进度条；失败时降级为「前往下载页」手动下载；Esc/遮罩可关闭（下载中锁定）
  - 状态收敛到 `state/updateStore.ts`（zustand），顶栏/对话框/设置页「软件更新」区块共享；启动时静默检查（断网/无 Release 不打扰）
  - 浏览器模式（非 Tauri）全部安全降级为 no-op

### 发布流水线（release-tauri.yml）

- 构建 step 传入 `TAURI_SIGNING_PRIVATE_KEY(_PASSWORD)` secrets，bundler 自动产出 `.sig` 更新包签名
- publish job 调整为：先建 draft Release（自动生成 What's Changed 正文）→ 取回正文嵌入 `latest.json` 的 `notes` 字段（客户端更新要点的数据来源）→ 上传 `latest.json` 与 `.sig`
- Release 需 publish（离开 draft）后 `releases/latest/download/` 才可解析，更新通道才生效

### 品牌图标

- 从 `assets/logo.jpg` 裁切机器人+霓虹三角徽标为 1024 方形源图，`npx @tauri-apps/cli icon` 生成全套：`icon.icns`（macOS Dock/启动台）、`icon.ico`（Windows 开始菜单/快捷方式）、32/64/128/128@2x PNG、Windows Store Logo
- 此前安装包使用的是 Tauri 脚手架纯色占位图（非品牌）

### 已知边界

- macOS 原地更新官方要求 app 代码签名；当前未签名包在 macOS 上若安装失败，UI 自动降级为手动下载页（Windows NSIS 未签名可正常原地更新）
- v0.9.1 及更早的安装包不含更新器，用户需最后手动安装一次 v0.9.2，之后版本均可自动更新

## 验证数据

- Rust：`cargo check` 干净通过（tauri 2.11 / updater 2.11 / process 2.3 / opener 2）
- 前端：vitest 622 个全绿（新增 releaseNotes 解析 5 条 + UpdateDialog 8 条 + 设置面板 5 条），`tsc --noEmit` 干净
- CI 配置：workflow YAML 校验通过；`latest.json` 生成与 Release notes 嵌入逻辑本地模拟通过
- Python 测试：2642 通过（2 个 `test_workbench_api.py` 失败为 Codex 环境相关的预存在问题，stash 验证与本版本无关）
- 端到端真实更新链路需在本版本发布后、下一版本发布时验证
