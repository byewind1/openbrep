# OpenBrep v0.9.1 发布说明

**发布日期**：2026-09-13

## 一句话总结

安装包真正独立可用：v0.9.0 的 Tauri 包只是个 2.7MB 的 Rust 壳（调系统 `python3` 跑源码），v0.9.1 把 Python 后端冻结成内嵌 sidecar，**下载安装即可用，不需要本机 Python 环境或源码**。

---

## 变更明细

### 冻结后端 sidecar

- 新增 `openbrep-backend.spec`：PyInstaller onefile 产物 `obr7-backend`，内嵌：
  - `openbrep` 包全部子模块与包内数据（`data/`、`prompts/`、`vision/schemas/`、`public_keys/`）
  - 知识库 free 层（`knowledge/`，排除 `ccgdl_dev_doc` 付费层）与 `skills/`
  - 前端构建产物 `frontend/dist`（Tauri 模式下由后端 `--static-dir` 服务）
  - litellm 数据文件与包元数据
- `src-tauri/tauri.conf.json`：`bundle.externalBin = ["binaries/obr7-backend"]`，Tauri 按目标平台三元组打包
- `src-tauri/src/main.rs`：启动时按候选路径（resource dir / binaries 子目录 / 可执行文件旁）定位内嵌 sidecar，找不到时回退开发态 `python3 scripts/obr7.py`；Windows 下 spawn 设 `CREATE_NO_WINDOW` 避免控制台窗口闪现

### `scripts/obr7.py` 冻结态支持

- 资源根：冻结态为 `sys._MEIPASS`，开发态仍为仓库根
- 运行时 cwd 落到 `~/.openbrep/workspace`（新建）：冻结态 root 是只读目录，`./output`、`./workdir`、`user_knowledge` 等 cwd 相对路径必须可写
- API 进程内运行（冻结二进制没有可用的 `python -m openbrep.workbench_api` 子进程）；`/api/shutdown` 后进程自然退出
- daemon 子进程在冻结态直接拉起二进制本身
- 配置文件解析保持既有语义：打包态无仓库 config 时落 `~/.openbrep/config.toml`

### 构建修复（v0.9.0 tag 首轮 CI 暴露的问题）

- `tauri.conf.json` 的 `beforeBuildCommand`/`beforeDevCommand` 钩子以 `src-tauri/` 为工作目录执行，原 `cd frontend` 在 CI 双双失败，修正为 `cd ../frontend`
- 补齐 Windows 构建必需的 `icons/icon.ico`（tauri-build 生成资源文件时强制要求）

### 发布流水线

`release-tauri.yml` 构建顺序变为：前端构建 → PyInstaller 冻结后端 → **冻结后端冒烟**（启动、`/api/snapshot` 可达、前端首页可服务，macOS/Windows 双平台）→ Tauri 打包 → 秘密门禁 → 上传。
