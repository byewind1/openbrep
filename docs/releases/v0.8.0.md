# OpenBrep v0.8.0

Release date: 2026-06-19

Release type: React Workbench default UI + self-correcting agent verification seam.

## Why

v0.8.0 is a major milestone: OpenBrep's primary UI switches from Streamlit to a
React + Monaco + Three.js code workbench, and the pipeline gains a first-class
Verification seam that turns scattered checks into a unified, proof-oriented
report. Together these move OpenBrep from "AI generates GDL" toward "verifiable,
self-correcting GDL development workbench."

## What changed

### React Workbench becomes the default UI

- Merged the `react-workbench` branch (72 commits) into `main`.
- `obr` now launches the React workbench by default (React 19 + Vite + Zustand +
  Three.js r3f + Monaco editor with GDL language/theme).
- Streamlit UI (`ui/` directory, `streamlit` dependency) is preserved as a
  fallback: `streamlit run ui/app.py` still works.
- If React workbench files are missing or startup fails, `obr` falls back to
  Streamlit automatically.
- FastAPI `workbench_api.py` + 13 `workbench/` service modules as the local API
  adapter layer (split from the original monolithic 1808-line file).
- `./obr7` launcher with automatic port fallback.

### Verification as a first-class seam

- New module `openbrep/verification.py` aggregates checks scattered across the
  pipeline (static checker, GDL linter, compile validation, object plan
  validation_checks) into a single `VerificationReport`.
- `run_plan_validation_checks()` turns `object_plan.validation_checks` (natural
  language) into executed pass/fail/unknown checklist items by mapping keywords
  to deterministic checkers (ADD/DEL balance, FOR/NEXT, IF/ENDIF, 3D-END,
  parameter consistency, 2D visibility). Unmappable items are reported as
  UNKNOWN — never silently passed.
- `build_verification_report()` produces a proof-oriented report with:
  - `passed` (only fails on blocking checks: static/compile/plan_check that ran)
  - `confidence` (high/medium/low — UNKNOWN and NOT_RUN lower confidence instead
    of failing)
  - `errors_caught`, `fixes_applied`, `remaining_risks`
- CREATE path reports compile as `not_run` (honestly exposing the gap; Phase 2
  will bring compile verification to CREATE).
- MODIFY path includes compile + auto-repair evidence.
- `Tracer` records verification summary (passed/confidence/counts/compile_status).
- React workbench `AssistantPanel` renders a `VerificationCard`: confidence,
  pass/fail/unknown/not_run counts, compile status, fixes applied, failed
  checks, unknown coverage, residual risks.

### CLI entry point

- `_launch_ui()` now prefers React workbench via `_has_react_workbench()` check.
- Falls back to Streamlit if React workbench is unavailable.
- `obr` opens the browser automatically (no `--no-open`).

### Docs SOP

- Cherry-picked落盘 SOP and Handoff SOP (CLAUDE.md/AGENTS.md) from main to the
  react-workbench branch before merge, ensuring AI collaboration rules are
  consistent across branches.

## Compatibility

- Archicad: AC28 / AC29 through LP_XMLConverter when available.
- GDL Copilot Add-On: AC29 macOS.
- Python: 3.10+.
- Node.js: 18+ (for frontend dev; `npm install` in `frontend/` required for
  first-time `obr` launch after merge).
- macOS package: Apple Silicon only (`arm64`, M1/M2/M3/M4), macOS 14 Sonoma or
  later.
- Streamlit fallback requires `pip install openbrep[ui]`.

## Known limitations

- Browser smoke test (Playwright) has a Monaco editor visibility timeout in
  headless mode — a pre-existing environment issue, not a code regression. The
  app fully loads; only the Monaco interaction step times out.
- Real LP_XMLConverter compile is code-complete but requires local converter
  configuration (Settings → LP_XMLConverter path).
- Tapir/Archicad live bridge has API and panel but is offline-untested on this
  machine.
- Settings Drawer closed state still exposes password values in the DOM
  (planned fix).
- CREATE path does not yet run compile verification (Phase 2, future).

## Migration notes

After updating to v0.8.0, first-time launch requires:

```bash
cd frontend && npm install
```

Then `obr` launches the React workbench automatically. If you need the legacy
Streamlit UI for Tapir/Pro workflows not yet migrated:

```bash
streamlit run ui/app.py
```
