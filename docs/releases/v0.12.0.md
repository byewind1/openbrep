# OpenBrep v0.12.0 发布说明

发布日期：2026-10-06

## 任务反馈与连续对话修复

本版本解决"任务失败/中断后无法复盘、同项目连续对话被打断、有进展的长任务被固定 90 秒窗口误杀、超时后迟到写入污染项目"四类核心问题。

### 执行过程可复盘

- 每个任务的执行过程以真实事件为唯一事实源，落盘到 `<项目>/.openbrep/memory/chats/tasks/<turn_id>.jsonl`：工具开始/结束（含真实耗时与调用关联）、验证、交付、取消、失败、公开说明。
- 聊天记录携带任务关联（task_ref）；重开项目后自动恢复执行过程时间线，进程退出前未完成的任务也会被发现并如实展示"任务未完成"，不伪造最终答复。
- 时间线支持分页查看全部步骤、15 秒等待提示（区分"等待模型响应"与"工具仍在运行"并显示各自耗时）、工具三态（运行中/成功/失败）。
- 事件记录不进入任何 LLM prompt（黄金语料回放字节级零退化）。

### 同项目连续对话

- AI 修改结果接入与 XML 保存刷新不再递增项目会话代次——同项目内可以连续咨询、修改、续做，不再出现"第二轮请求被 PROJECT_CHANGED 拒绝"。
- 打开/关闭/新建/导入/切换/恢复 revision 等项目激活入口保持旧请求失效语义；执行响应携带服务端当前身份，过期令牌明确提示，不跨项目盲重发。

### Agent 超时独立可配置

- 新增 `[agent]` 配置：`agent_idle_timeout`（默认 180 秒，无有效活动上限）、`agent_task_timeout`（默认 1800 秒，整个任务总上限，普通与 Codex 两条引擎一致）、`agent_tool_timeout`（默认 600 秒，单工具上限）。普通 `llm.timeout` 恢复只约束单次文本调用。
- 有有效活动（模型输出、工具开始/结束、协议进展）的任务不会被固定窗口误杀；超时原因结构化区分（idle/task_deadline/tool_timeout/cancelled），保留部分修改与交付证据，不透明重跑。

### 迟到写入隔离与原子提交授权

- 工具超时/取消/项目切换后，迟到的源码写入在提交点被授权检查拒绝并隔离，不会污染共享项目状态；每回合与每次调用持有独立不可复活的授权令牌，门禁打回后的下一回合创建新授权。
- 源码变更的校验与提交在同一原子边界内完成；已提交的变更是真实部分修改，未提交的失效结果被丢弃。
- 关键写入被拒且无后续有效修复时，任务如实标记未完成——即使验证门对当前源通过也不假称成功。

### 其他

- Codex 订阅模型的公开说明（commentary）实时转发并落盘，与最终答复分离；隐藏推理不采集。
- 聊天的咨询、失败、取消等全部结果立即保存并关联任务，异常退出后可复盘。
- 执行记录保存失败时界面明确提示，任务继续但不再谎报记录完好。

## 安装与升级

| 平台 | 安装包 | 架构 |
|---|---|---|
| macOS Apple Silicon | `OpenBrep_0.12.0_aarch64.dmg` | arm64 |
| macOS Intel | `OpenBrep_0.12.0_x64.dmg` | x86_64 |
| Windows | `OpenBrep_0.12.0_x64_en-US.msi` 或 `OpenBrep_0.12.0_x64-setup.exe` | x86_64 |

macOS 兼容性将在发布草稿产物上按全部 Mach-O 可执行文件与动态库的最高 `minos` 复核。上一完整正式包实测为 Apple Silicon 需要 macOS 13.5 或更高版本，Intel 需要 macOS 15.0 或更高版本；本版本打包链路未变，预计一致，以草稿产物复核为准。Windows 在 GitHub Windows runner 完成冻结后端冒烟；本轮不声称额外的 Windows 桌面真机验收。

安装包内嵌 Python 后端，无需本机 Python。已安装用户可通过应用内更新升级，或下载对应架构安装包覆盖安装。macOS 包尚未完成 Developer ID 签名和 Apple 公证；必要时按安装指南处理隔离提示。
