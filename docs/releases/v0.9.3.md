# OpenBrep v0.9.3 发布说明

**发布日期**：2026-09-14

## 一句话总结

稳定性补丁：修复桌面安装包**启动即崩溃**的问题（v0.9.0–v0.9.2 均受影响）——`tauri.conf.json` 静态声明了 `main` 窗口而 `main.rs` 又用同名 label 程序化建窗，label 冲突导致 setup 失败、进程 abort。

---

## 变更明细

### 修复：桌面 app 启动即崩溃（SIGABRT）

- 现象：双击 OpenBrep.app 立即崩溃，崩溃报告为 `abort() called`（`a webview with label 'main' already exists`）
- 根因：窗口需要等待后端吐出动态 URL 才能创建，因此 `main.rs` 在 setup 里用 `WebviewWindowBuilder` 手动建 `main` 窗口；但 `tauri.conf.json` 的 `app.windows` 同时静态声明了同名窗口，Tauri 启动时自动创建，两者冲突
- 修复：`tauri.conf.json` 的 `app.windows` 置空，窗口只由代码创建；窗口尺寸/标题等参数本就以 `main.rs` 为准
- 为什么之前没发现：CI 冒烟只验证了独立的冻结后端（`obr7-backend` 命令行），从未在真机上启动过完整 `.app`；本次已在本地真实启动验证修复
- 流程加固：Release SOP 增加"发布前在本机真实启动一次打好的 .app"验证项
