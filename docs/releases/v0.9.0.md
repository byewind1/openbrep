# OpenBrep v0.9.0 发布说明

**发布日期**：2026-09-13

## 版本口径说明

本仓库在 2026-06-21 曾以 **v1.0.0** 口径准备 Tauri 桌面工作台发布（更新了版本号与发布文档），但该版本从未打 tag、未发布 GitHub Release。经维护者决定，**撤回 1.0 编号**：本次里程碑以 **v0.9.0** 正式发布，1.0 留给后续更完整的产品形态。本说明取代原 `docs/releases/v1.0.0.md`。

## 里程碑总结

v0.9.0 是架构完成态版本。从 v0.8.0 起历经 Streamlit 退役 + Tauri 桌面壳两轮大重构，OpenBrep 从基于 Streamlit 的 Web 工具演变为可分发的原生桌面应用；此后又累积了两个多月的生成质量、视觉输入、图库依赖与桌面集成工作。

## 核心变更

### Streamlit 完全退役

删除 `ui/` 目录全部 79 个文件及 24 个 Streamlit 相关测试。三个包含域逻辑的纯函数文件迁移到合适位置：

| 原路径 | 新路径 |
|--------|--------|
| `ui/view_models.py` | `openbrep/workbench/view_models.py` |
| `ui/three_preview.py` | `openbrep/workbench/three_preview.py` |
| `ui/local_file_dialog.py` | `openbrep/local_file_dialog.py` |

所有 import 引用同步更新，`pyproject.toml` 移除 streamlit / streamlit-ace / plotly 依赖。

### Tauri v2 桌面壳

新增 `src-tauri/` 目录，包含：

- `src/main.rs`：Rust 主进程，spawn Python sidecar，读取 stdout `OBR7_READY_URL=` 信号，打开 Webview 窗口，关窗时发 `/api/shutdown` 并等待进程退出
- `tauri.conf.json`：产品元数据（identifier: `com.openbrep.app`，窗口 1440×900 / 最小 1024×700）
- `rust-toolchain.toml`：锁定 rustup stable，避免 Homebrew rustc 冲突

`workbench_api.py` 新增 `--static-dir` 单端口模式：同时服务 API 与 `frontend/dist/` 静态资源，带路径遍历防护与 SPA index.html fallback。`scripts/obr7.py` 新增 `--tauri` flag，打印机器可读信号供 Rust 读取。

防御性加固：Python stderr piped + relay thread（崩溃堆栈可见）、启动 60s 超时硬失败（不再打开死窗口）、关窗 kill 后等待最长 3s 确认孤儿进程退出、Vite 注入 `VITE_IS_TAURI`。

### 生成与验证质量（2026-07 ~ 2026-08）

- **语义修复环**：编译通过后 CREATE 与 MODIFY/DEBUG/REPAIR 运行 `verify_semantics`，阻塞性问题触发有界接受/回滚修复轮（`openbrep/runtime/semantic_repair.py`）；`TaskResult.success` 即验证报告的 `passed`，作为交付门禁
- **命名对齐**：`openbrep/naming_alignment.py` 按可插拔命名规范重命名参数；保留字维度角色误用（高度塞进 A/B 等）成为阻塞性检查
- **确定性微修改**：纯参数值修改（"把层板数改成 5"）在 LLM 路径之前拦截，高精度识别，歧义即回退原路径
- **验证防御包**：修复轮拒绝退化产物（省略号桩、内容缩水、参数丢失）；CREATE 运行交付完整性检查
- **Agent-loop 写入防护**：markdown 散文泄漏进 .gdl 会阻塞 `update_script`/`patch_script` 写入；paramlist 字符串值在被脚本引用时受保护
- **Archicad 兼容性**：String 参数值序列化为带引号 CDATA；GSM `Owner`/`Signature` 默认补 Graphisoft 注册魔数（编译期归一化）

### 视觉输入（Vision Harness）

图片输入走 `openbrep/vision/harness.py` 四段管线（本地 schema 分类 → schema 驱动抽取 → critic → hint 组装），schema 以 YAML 注册。CREATE 带图在抽取后暂停等用户确认；抽取结果以内容寻址持久化，MODIFY 复用缓存。非交互路径（benchmark/CLI）与旧行为字节级一致。

### GSM CALL 宏依赖与 2D 预览（2026-09-12）

- `HSFProject` 无损往返 `calledmacros.xml`、完整祖先 GUID 链、Identification 标志与 `libpartdocs.xml`
- 预览器执行 `CALL`：注入式宏解析（`MacroLookup` 协议），隔离调用帧、深度/次数/墙钟预算门禁
- 图库上下文 `openbrep/library_context.py`：文件夹 / .lcf / .libpack 根，GUID 优先解析，内容寻址转换缓存
- 2D 覆盖真实图库符号：统一 POLY2 引擎（含 POLY2_B{5} 圆弧、frame_fill 位、孔洞拆分）、富文本链（DEFINE STYLE / PARAGRAPH / TEXTBLOCK / RICHTEXT2）

### Copilot 集成（2026-08-13）

Archicad 插件的 copilot 后端并入工作台：`openbrep/workbench/copilot_service.py`（状态/对话/剪贴板缓冲/错误摘要），路由 `/api/copilot/*`；`obr serve` 成为 C++ 插件唯一启动入口；前端 `?mode=copilot` 渲染独立页面。

### 模型与供应商管理

- 统一供应商注册表：`[[llm.providers]]` 端点式供应商单一机制，旧 `custom_providers` 载入时归一化
- 会话级模型覆盖：`POST /api/session/llm/model` 只改会话，不写 config.toml
- 模型可见性：纯 UI 策展（localStorage），配置过的供应商默认可见

### 质量台账与经验蒸馏（2026-09-05）

- 每次 `TaskPipeline.execute()` 获得稳定 `run_id`，产出不可变质量记录 `.openbrep/quality/runs/<run_id>.json`；观察-only，不进 prompt
- Reflector/Curator：扫描质量台账产出候选 → LLM 蒸馏为带证据引用的 lesson → 一律 `proposed`，由人在工作台审批

### Benchmark 黄金语料回放

LLM 效果验证采用录制/回放（`benchmark/llm_replay.py`）：录制一次语料后离线确定性回放，CI `benchmark-replay` job 与 `benchmark/baseline.json` 比较，退化即红灯。

## 已知限制 / TODO

- **SSE 流式输出**：需在真机 Tauri Webview 中验证 `Transfer-Encoding: chunked` 行为
- **PyInstaller 旧流水线**：`build-installers.yml` 不再随 tag 自动触发（保留 workflow_dispatch 手动入口），发布产物以 Tauri 流水线（`release-tauri.yml`）为准

## 升级路径

从 v0.8.x 升级：

```bash
git pull origin main
pip install -e "."        # 依赖有变化（streamlit 系已移除）
cd frontend && npm install
```

`config.toml` 格式兼容，无需改动。
