# GDL 几何命令选择规则

生成或修改 GDL 时，几何命令的选择决定可编译性、可参数化程度、预览稳定性与
三角面数量。本规则给出「能低不高」的复杂度阶梯，以及每个主要命令的
「何时用 / 何时不用」。适用路径：CREATE（生成）、MODIFY / DEBUG / REPAIR
（修改与修复）；用户明确要求「优化 / 审查」时，按文末「审查模式」小节执行。

## 复杂度阶梯（能低不高）

阶梯从低到高。默认从最低可用级别开始，只有出现对应「正当理由」才升一级。
升级到高阶命令时，必须在规划或代码注释里写明理由（自查口）。

1. **BLOCK / BRICK / CPRISM_**：盒体 / 板件（默认首选）
   - 何时用：矩形六面体、板件、简单盒子。零理由即可使用。
   - 升级理由：不是正六面体（斜面、异形截面）、需要独立顶 / 底 / 侧面材质
     （CPRISM_ 按面给材质）、需要非直角端面。

2. **CYLIND / CONE / SPHERE / ELLIPS**：解析回转体 / 球
   - 何时用：圆柱、圆锥、球、椭球等单个解析曲面可完整表达。
   - 升级理由：单一解析形状无法覆盖（台阶式柱身、带颈花瓶、鼓肚立柱）。

3. **PRISM_ / BPRISM_**：任意 2D 轮廓竖直拉伸
   - 何时用：异形板件、带缺口的轮廓、非矩形截面沿 Z 拉伸。
   - 升级理由：轮廓需要圆角（BPRISM_ 顶点圆角曲线）；拉伸方向非竖直或
     顶面需要倾斜 → 升 EXTRUDE。

4. **EXTRUDE**：轮廓拉伸（顶面平移 / 倾斜）
   - 何时用：轮廓沿 Z 拉伸但顶面可整体平移（dx, dy, dz），适合斜面顶、
     错位顶、非竖直拉伸。
   - 升级理由：轮廓要绕轴旋转 → REVOLVE；沿弯曲路径 → SWEEP。

5. **REVOLVE**：真旋转体（轮廓绕轴旋转）
   - 何时用：花瓶、柱头、栏杆立柱、球碗、台阶式圆柱等「绕一根轴旋转对称」
     的形体。
   - 正当理由：必须写明「确实是旋转体」。简单圆柱优先用 CYLIND；
     旋转轮廓不能包含孔（基础语法）。

6. **SWEEP**：轮廓沿路径扫掠
   - 何时用：截面沿弯曲路径移动（扶手、弯轨、异形管道）。
   - 正当理由：必须写明「路径确实弯曲」。直线路径用 PRISM_/EXTRUDE 更稳；
     复杂路径先做低点数可编译版本，再细化。

7. **TUBE**：3D 路径管（等截面沿空间路径）
   - 何时用：3D 空间中的弯曲管、扶手、画框。最难写对，最后考虑。
   - 纪律：首尾路径点是 phantom 点；截面多边形必须闭合；
     先用低路径点数出可编译版本（cookbook「Swing the Cat」循环法）。

8. **RULED / COONS**：两轮廓蒙皮 / 自由曲面
   - 何时用：两个不同截面之间的蒙皮、翘曲面（双曲抛物面等）。
   - 纪律：先确认确有需求；COONS 需要四条边界曲线，数据量比想象大。

9. **MESH / PGON 面片拼装**：最低层级手段
   - 何时用：显式网格导入（Blender 等）、无法用上述命令表达的雕塑曲面。
   - 纪律：生成代码绝不手写大量 PGON 顶点；面片顺序、孔洞与共用边极易错。

## 减法与加法取舍

切口（斜切、开洞、槽口）优先评估「减」是否比「加」简单，而不是盲目多件拼装：

- **CUTPLANE**：平面斜切 / 削顶。比造多个体再拼简单，切完必须 CUTEND。
  切平面参数基于定义时刻的坐标系；CUTPLANE 与 CUTEND 之间的变换移动的是
  被切几何，不是切平面本身。
- **CUTPOLY / CUTFORM**：多边形轮廓切 / 成型切割。轮廓定义方式与 PRISM_
  相似，注意状态码与闭合规则。
- **GROUP 布尔（ADDGROUP / SUBGROUP / ISECTGROUP）**：联合 / 差集 / 交集。
  GROUP 定义本身不产生可见几何，必须 PLACEGROUP；只在简单命令确实做不到时
  使用（如扫掠体布尔），首轮生成避免依赖 GROUP 布尔。
- 通用口径：先按「加」规划；遇到斜切、开洞、直角相交裁切时，若减法命令
  （尤其 CUTPLANE）表达更短，改用减法并说明理由。

## 建模前决策清单

生成任何对象前按顺序自问（cookbook 0041-0050 提炼）：

1. **形体分解先行**：这个构件的最基本形体是什么？（盒子 / 柱 / 旋转体 /
   拉伸件 / 管）先写形体分解，再选命令，不要默认 BLOCK 拼装。
2. **需要参数化拉伸吗？** 需要 → PRISM_/EXTRUDE 族（轮廓点由参数驱动）；
   只是固定几何 → 仍首选低阶命令，别为「参数化」硬上高阶命令。
3. **能否用 2D / 贴图表达？** 树叶、瓷砖、人物等细节用贴图或 2D 表达，
   不要做成高精度 3D 曲面（性能与稳定性更好）；人能、树等可用卡片剪影
   替代高面数 3D。
4. **是否需要那么「聪明」？** 少量可参数项即可时，别把对象做成
   全自动智能体——过度参数化反而难维护。
5. **复杂轮廓：先简后繁**：先生成简化可编译版本（低顶点数、直线近似），
   再逐步细化，不要一次到位。
6. **切口优先评估减法**：见「减法与加法取舍」。

## 各命令的「何时用 / 何时不用」

- **BLOCK**：矩形板件、盒体随意用；不用它表达斜面、圆、异形轮廓。
  BRICK 与 BLOCK 同族；CPRISM_ 家族在需要分面材质时升级。
- **CYLIND**：杆件、圆管、圆盘、螺栓孔。参数顺序是 `CYLIND h, r`
  （高度在前），别写反；`h = 0` 退化为圆、`r = 0` 退化为线。
  简单圆柱不要用 REVOLVE/SWEEP 绕。≥4 个同半径同轴 CYLIND 顺序堆叠 =
  应改用 PRISM_/REVOLVE 单轮廓（static_checker 会提示）。
- **CONE / SPHERE / ELLIPS**：圆锥、球、椭球这类解析形状直接用；
  不用它们拼复杂轮廓（台阶锥台改用 REVOLVE/PRISM_）。
- **PRISM_**：任意 2D 轮廓沿 Z 拉伸；`PRISM_ n, h, x1, y1, s1, ...`
  的 n 必须与坐标组数量一致；状态码 15 = 全边可见最常见，64 = 仅轮廓线
  （曲面用）。不用它表达旋转体或弯曲路径。
- **BPRISM_**：轮廓顶点需要圆角时；圆角半径语义随顶点列表。
- **EXTRUDE**：顶面需要倾斜 / 平移的拉伸件；不用它做竖直矩形拉伸（BLOCK
  更短）或旋转体。
- **REVOLVE**：绕轴旋转对称形体；不用它做简单圆柱（CYLIND 更快渲染），
  不用 POLY2 id + REVOLVE id 的伪语法（轮廓必须内联）；轮廓凹入轴心可能
  自交；360° 的端面会自动封口。
- **SWEEP**：截面沿弯曲路径；路径严重弯曲会自交、平行切线段会歧义
  （插微小拐点），复杂截面会把面数按路径段数放大；不用它做直线拉伸。
- **TUBE**：3D 弯曲等截面管；最难写对，先低顶点版本；截面必须闭合；
  不用它做竖直直管（CYLIND/EXTRUDE 更简单）。
- **CUTPLANE**：斜切 / 削顶 / 切角；每次 CUTPLANE 必须配 CUTEND，
  否则影响后续所有几何；不用它做 2D 平面表达（那是 PROJECT2 的职责）。
- **GROUP 布尔**：差 / 交 / 并、扫掠布尔；务必 PLACEGROUP；
  不用它做简单叠放（BLOCK + 变换即可）。
- **RULED / COONS / MESH / PGON**：自由曲面与显式网格；没有明确需求
  就不出现。

## 慎用清单

- 不以 BODY / EDGE 级手工构造作为主策略（无头环境不可控、易错）；
  仅显式网格导入 / 雕塑曲面场景使用，且尽量复用导入代码而非手写。
- 不以 GROUP 布尔作为默认组合手段：先评估 CUTPLANE 减法与普通体叠加。
- 不在首轮生成里堆高阶命令：先保证可编译、可预览，再谈细节。

## 审查模式（优化 / 审查请求专用）

当用户输入命中「优化 / 审查 / 检查 / 改进 / 精简 / refactor / optimize /
review」类意图且当前有打开项目时，本规则全文被强制注入提示词。此模式下：

- **输出必须是选型评估，不是直接改写**：对照本阶梯，逐个主要形体说明
  当前命令选择是否合理、有没有更低阶替代、理由是什么。
- 评估结构：每个主要形体一行结论（合理 / 可降阶 / 应升阶），附一句理由；
  最后汇总可改进点清单。不输出 [FILE:] 改写块——用户确认后才进入 MODIFY
  执行。
- 若当前选型已经是最低合理阶，明确写「合理，无需改动」，不为了「优化」
  而优化（避免无谓重构）。
- 审查的检查点：阶梯是否合理（能低不高）、重复同构体是否该合并为
  FOR/NEXT 或单轮廓、CUTPLANE 系减法是否该替代多体拼装、复杂网格是否有
  解析命令替代。
