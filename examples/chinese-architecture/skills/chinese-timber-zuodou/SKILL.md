# 坐斗：从参考图到可编辑 GDL

## 适用场景

坐斗、四耳坐斗、坐斗棱台、坐斗内侧连接块、zuodou。
只在参考图或用户要求符合本案例的构造时采用这套组合；其他斗形需要重新判读。

## 先确定几何关系

1. 将主视、侧视、俯视和轴测图映射到统一坐标。本案例原点在底面中心，X 为左右，Y 为前后，Z 向上。俯视图上方为 +Y，前侧为 −Y；它们是建模约定，不是建筑朝向。
2. 按高度分成：**下部上大下小的四边棱台 → 等截面斗身 → 四个高斗耳及两条低连接块**。中央槽底是斗身顶面，不是穿透底座的洞。
3. 本案例两条连接块沿 X 连接同侧左右斗耳，分别位于 ±Y 一侧。它们低于耳顶，朝向中央槽口的面与斗耳内侧面共面。四个孤立 BOX、沿外缘连接、四边全部封闭，都是不同的形状。
4. 将用户校正写成具体关系：“低连接块与斗耳**内侧**对齐”。不要把屏幕上的“上/下两个 box”直接当世界坐标，旋转视图后关系仍应成立。
5. 尺寸分清来源：图纸标注、用户指定、沿用原项目、暂定比例。本案例低块高为耳高的 1/3、厚为耳深的 1/2，属于暂定值；后续明确尺寸优先。

## 按几何需要选命令

| 局部 | 需要表达的几何 | 本案例方法 |
|---|---|---|
| 下部 | 上下矩形不同大小，四个连续斜面 | `RULED`，四对对应顶点 |
| 斗身 | 等截面的矩形实体 | `BLOCK` 或 `PRISM_` |
| 四耳 | 同一标高的四个角部矩形实体 | 四个 `BLOCK` |
| 两条低连接块 | 连接斗耳，内侧齐平，保留中央槽 | 两个 `BLOCK`，位置由内边界计算 |

不要因为 BLOCK 更简单，就把连续收分改成多层台阶。先检查命令能否表达所需形状，
再比较复杂度。若参考是曲线收分，四个平面只可作为用户认可的简化。

## RULED 的最小正确用法

下轮廓在当前局部 XY 平面；每个节点为 `(u, v, status)`。
上轮廓每个节点为 `(x, y, z)`，与下轮廓节点一一对应。
本例四个不重复角点按相同绕向排列，用 mask 的 `4` 闭合最后一侧。

```gdl
! bw/bd: bottom width/depth; tw/td: top width/depth; h: taper height
RULED 4, 119,
  -bw/2, -bd/2, 0,
   bw/2, -bd/2, 0,
   bw/2,  bd/2, 0,
  -bw/2,  bd/2, 0,
  -tw/2, -td/2, h,
   tw/2, -td/2, h,
   tw/2,  td/2, h,
  -tw/2,  td/2, h
```

要求 `0 < bw < tw`、`0 < bd < td`、`h > 0`。
`119 = 1 + 2 + 4 + 16 + 32 + 64`：底、顶、闭合侧面及三组可见边。
下轮廓第三个数 `0` 是边状态，不是高度；上轮廓第三个数才是 Z。
上面保持共面，避免扭转或缺盖。
完整语义见 [Graphisoft RULED 文档](https://gdl.graphisoft.com/reference-guide/shapes-generated-from-polylines/#RULED)。

## 内侧对齐的坐标公式

设槽宽 `_slot_w`、槽深 `_slot_d`，则斗耳内边界为
`_ear_x = _slot_w/2`、`_ear_y = _slot_d/2`。
连接块厚度 `_rail_d` 沿 Y，高度 `_rail_h` 沿 Z。

在已经 `ADDZ` 到斗身顶面、尚未退出该变换的坐标系中：

```gdl
! Front: inner face is y = -_ear_y
ADD -_ear_x, -_ear_y - _rail_d, 0
BLOCK _slot_w, _rail_d, _rail_h
DEL 1

! Back: inner face is y = +_ear_y
ADD -_ear_x, _ear_y, 0
BLOCK _slot_w, _rail_d, _rail_h
DEL 1
```

要求 `0 < _rail_d <= _ear_d`、`0 < _rail_h < _ear_h`。
两块 X 范围均为 `[-_ear_x, +_ear_x]`，两端与耳接触；前块的 **maxY** 是 `-_ear_y`，
后块的 **minY** 是 `+_ear_y`。别使用外缘公式 `-_ear_y-_ear_d` 和
`_ear_y+_ear_d-_rail_d`，它们会得到曾被用户否定的位置。

## 修改与验收

- 读取当前 HSF 的 Master、3D 和参数。已有项目只改目标局部，保留正确的棱台、斗耳和尺寸关系；通过 HSFProject / 工作台源事务保存，并保留可回退版本。
- 新建模型使用 `A` 为实际总宽、`B` 为实际总深、`ZZYZX` 为总高。参考模板位于 [assets/zuodou](assets/zuodou/)；旧项目改参前需先核对其真实尺寸语义。
- 先检查保存后的源码与编译结果，再分别核对：四个斜面、顶部接斗身无缝、四耳位置、两条低连接块的内边界及中央槽口。总包围盒相同不能证明连接块位置正确。
- 俯视确认内侧对齐，正/侧视确认高差与收分，轴测确认组合。等高截面应随 Z 连续放大，不能出现台阶；只数 BLOCK 或三角形数量不够。
- 在可用时检查非正方形尺寸，避免把 B 的计算误写为 A。多个接触实体不等于已布尔并成一个实体；任务需要单一实体时单独处理。
- 分开报告：源码已保存、LP 编译通过、本地预览检查、Archicad 宿主显示、用户确认。缺失的验收不标为通过，编译成功不能代替图形正确。

## 案例背景与边界

需要了解演变、参数来源、反例与验证记录时，读取 [案例复盘](references/case-study.md)；
需要辨别内外缘时，看 [俯视示意](references/top-view.svg)。
需要重新验证模板时，运行 [scripts/verify_example.py](scripts/verify_example.py)；
从 OpenBrep 仓库根目录使用 `PYTHONPATH=.`，加 `--compile` 可调用已安装的 LP_XMLConverter。
脚本只读模板、使用临时目录，不调用模型；它检查这个模板的约定，不是任意坐斗的通用验收器。
这是具体坐斗的建模案例，不是清式/宋式斗口制标准，也不包含木工榫卯、受力验算或整攒斗拱。
